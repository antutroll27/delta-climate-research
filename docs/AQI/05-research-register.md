## 1. Evidence-status vocabulary

| Status | Meaning |
|---|---|
| Verified | Checked against an authoritative source or the repository artefact |
| Research snapshot | Checked on the stated date; expected to change and must be refreshed |
| Decision | Agreed implementation direction based on current evidence |
| Open | Needs validation before the dependent feature ships |
| Superseded | Earlier repo assumption replaced by newer evidence |

| AQI-R49 | Decision 29 Sep | **The Pi relay submits to OBOS through a signed ingest endpoint and never holds a storage credential** (design D2, `docs/superpowers/specs/2026-09-29-pi-india-service-design.md`). The Pi keeps only `RELAY_HMAC_KEY` (32+ random bytes). Each submission carries `X-OBOS-Timestamp` and `X-OBOS-Signature: v1=HMAC-SHA256(key, "<ts>.<SHA-256(body)>")`. OBOS checks the timestamp within 300 s (the replay window), compares the MAC in constant time, caps the body at 1 MB and its inflation at 2 MB, and parses it with the audited `parseFeed` (at least 300 stations, one `lastupdate`, not more than 15 min ahead or 7 days old) before writing private Vercel Blob; archive files are write-once. **Why:** relay plan v0.2 gave the Pi a Blob read-write token, so a stolen Pi could overwrite `latest` with any bytes and delete the archive; with the key it can only submit what already passes OBOS's parser, and rotation is one variable on each side. A malformed key is treated as unset (503), because Node's `Buffer.from('zz', 'hex')` is empty and an empty-key HMAC is forgeable. Go and TypeScript are proven to sign identically by `tests/fixtures/pi/hmac-vectors.json`, generated independently by Python (the ping vector also checked with OpenSSL). | Implemented on `feat/pi-india-service` (`api/air-quality-ingest.ts`, `src/lib/aqi/relay-auth.ts`, `pi/internal/ingest`). Serving is still guarded by `pick()` and the freshness states. A leaked key is rotated per `pi/deploy/README.md` §5; a Vercel env change reaches only new deployments, so rotation includes a redeploy. |
| AQI-R50 | Decision 29 Sep | **A dead relay hands the card over to OpenAQ after 2 h, instead of showing CPCB's value as stale for up to 7 days** (founder, after the pre-ship audit). In relay mode a stored feed whose `lastupdate` is older than `LIVE_H` (2 h) counts as a failure (`requireLive` in `src/lib/aqi/cpcb-feed.ts`), so `/api/air-quality` falls back to OBOS's own reading from OpenAQ, exactly as when CPCB is unreachable in direct mode. The audit showed the old rule (freshness from `lastupdate` alone) let a Pi that went offline keep serving a stale CPCB number for a week, cached for 10 min, while OpenAQ was live. Caveat: OpenAQ's Indian data has been frozen since 24 Sep, so until it recovers the fallback reading is itself marked old. The same audit made `latest` move only forward (an older hour is archived but never replaces it) and the Pi skip any feed not later than the last one it sent. Spec §5, §8a. |

## 6. Change-control rule

When a dynamic fact changes, update this register and the affected product decision
in the same pull request. Do not silently update a station mapping, AQI algorithm or
licensing assumption in code alone. Changes to the calculation method require a new
algorithm version and reproducibility fixtures.
